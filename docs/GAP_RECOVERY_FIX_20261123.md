# 采集遗漏恢复修复（2026-11-23）

本次只修复代码与配置，没有启动正式补采、重置生产游标或修改历史数据。

## 修复范围

- **LNC**：`retry_http_statuses: [400]` 只为该站启用旧 400 的冷却后重试。保留每轮次数限制；其他站的 400、404 等不会因此重新入队。
- **MECDM**：启用 `documents: true`。HTTP 与 curl_cffi 保留 PDF 二进制，使用固定版本 pypdf 7.0.1 提取正文和元数据，子进程解析有超时。超大响应、损坏文件、解析失败进入失败队列，不标成功。历史文档路由的 `skipped/no_text` 会在下次运行重新入队。
- **PDF 原件**：保存到 `data/<domain>/attachments/<sha256>.pdf`；相同内容只保存一份原件，每个来源 URL 各有一份 JSON 回执。正文行仍按来源 URL 保存，不把不同来源关系丢掉。没有文字层的 PDF 保留元数据，并在回执中明确标记 `no_text_layer`；本次未接 OCR。
- **TNTV**：为 posts 配置 `backfill_revision: {posts: 1}`。下一次运行从列表起点核对缺失条目，已保存 URL 仍去重；中断后按当前游标续跑，同一版本完成后不重复重扫。HTTP 与浏览器 WP 通道、监督器均识别此配置。
- **Samoa**：复用现有 SQLite 请求队列保存详情 URL 和列表元数据。失败可跨运行重试，写盘成功后才标 done；列表到尾但仍有未解决详情时为 partial。配置一次历史重扫以重新发现旧版本未持久化的失败 URL，保留原数据。
- **完成状态**：404/410 只根据错误开头的 HTTP 状态判断，避免正文中含有“404”导致 500 被当成已删除。

配置修改不代表已经完成补采。已有 `CRAWL_PAUSED` / `CRAWL_SKIP` 仍生效；本次没有移除暂停标记。恢复时继续使用原采集入口即可，无需删库或清空数据。
