# A/B 实测：抓取出口与降噪（2026-11-09）

回应"直连快数十倍 / route.abort 省 60% / 降噪 90%"这类说法。所有数字来自本机同一批页面，
只读、不写 `data/`。复现脚本：[`collector/bench_ab.py`](../../collector/bench_ab.py)。

样本：gov.nu（直连可访问的静态站）6 篇；upng.ac.pg（Cloudflare JS 挑战站）6 篇。
正文可用性用项目线上同一条链路判断（`extract_best`，正文 ≥120 字算成功）。

## 1. 抓取出口（每页平均耗时 / 成功率 / 平均正文 / HTML 字节）

### gov.nu（直连就能拿到的站）

| method | 平均耗时 | 成功率 | 平均正文 | 标题/日期 | 平均字节 |
|---|---|---|---|---|---|
| direct | **0.47s** | 6/6 | 1,821 | 6/6 · 6/6 | 27.4 KB |
| impersonate (curl_cffi) | 1.05s | 6/6 | 1,821 | 6/6 · 6/6 | 27.4 KB |
| ego（本机 Chromium） | 3.75s | 6/6 | 1,821 | 6/6 · 6/6 | 63.7 KB |
| playwright（headless） | 3.06s | 6/6 | 1,821 | 6/6 · 6/6 | 63.7 KB |
| playwright + 资源拦截 | 3.58s | 6/6 | 1,821 | 6/6 · 6/6 | 63.7 KB |

结论：对直连可用的站，浏览器**没有带来任何正文增量**，耗时约 **6–8 倍**，HTML 体积 2.3 倍
（渲染后的 DOM）。资源拦截在这类小页面上**没有加速**（反而略慢，噪声级差异）。

### upng.ac.pg（Cloudflare JS 挑战，直连只拿到挑战页）

| method | 平均耗时 | 成功率 | 平均正文 | 标题/日期 | 平均字节 |
|---|---|---|---|---|---|
| direct | 0.35s | **0/6** | 0 | 0/6 · 0/6 | 12.0 KB（挑战页） |
| ego（本机 Chromium） | 4.04s | **6/6** | 824 | 6/6 · 6/6 | 48.1 KB |
| playwright（headless + Chrome UA + 轻度反自动化） | 3.88s | **5/6** | 707 | 5/6 · 5/6 | 40.4 KB |
| playwright + 资源拦截 | 4.14s | **6/6** | 824 | 6/6 · 6/6 | 48.1 KB |

结论：
- 浏览器路径是**唯一能拿到内容**的方式（直连/指纹模拟 0/6），这就是 UPNG 从 3 行变成 35 行的原因。
- **Playwright 可以替代 ego**：在正确设置 Chrome UA、`navigator.webdriver` 清理、等待 ~3s 后，
  成功率和正文长度与 ego 持平（5–6/6 vs 6/6，824 字），耗时相近（3.9s vs 4.0s）。1 次失败是
  Cloudflare 挑战页刷新未完成（等待偏短），可通过 `playwright_wait_ms: 3000` 覆盖。
- 资源拦截在 UPNG 上也没有明显收益。

## 2. 降噪（gov.nu，8 篇，同一份 HTML）

| extractor | 平均字符 | 相对原始 HTML 压缩率 | 备注 |
|---|---|---|---|
| 整页粗抽（`text.clean`） | 4,412 | 84.0% | 含导航/页脚，基线 |
| trafilatura 纯文本 | **1,928** | **93.0%** | 线上默认 |
| trafilatura Markdown | 1,938 | 93.0% | 含格式标记 |
| readability-lxml + markdownify | 2,322 | 91.6% | 比 trafilatura 多约 20% |

抽样对比：readability 多出来的内容主要是文末的**新闻联络信息**（"For further information /
Anzee Mougavalu / GON Communications Officer …"），不能简单判定为噪声；trafilatura 更激进地
裁掉了它。两者都远好于整页粗抽（相对粗抽文字量减少约 56%）。

结论："降噪 90%" 只在"相对原始 HTML 字节"的口径下成立（≈93%）；相对"整页可见文字"约 56%；
没有证据支持"readability/Crawl4AI 一定更干净"。Crawl4AI `fit_markdown` 未实测（95 个依赖，
且需 Playwright/浏览器安装），暂不作为默认。

## 3. 摆脱 ego 依赖的论证（服务器部署）

现状：`ego` 是 macOS 上的本地 Chromium（`ego-browser` CLI + 持久 profile），**不能直接部署到
Linux 服务器**。当前 74 个站里：67 直连、4 TLS 指纹、3 ego（norfolk / upng / 另一处），浏览器
只在挑战站上必要。

实测结论：**Playwright 可作为服务器端替代**：
1. `via: playwright` 已接入（[`browser_playwright.py`](../../collector/crawler/browser_playwright.py)），
   支持 `playwright_wait_ms` / `block_resources` / `headless` 配置；未安装依赖时给出明确错误。
2. 本机验证用缓存 Chromium（`PLAYWRIGHT_EXECUTABLE` 指向 ms-playwright 的 chrome-headless-shell）；
   服务器标准安装：`uv sync --extra browser && python -m playwright install --with-deps chromium`。
3. 同一 UPNG 页面 Playwright 与 ego 产出正文一致；CF JS 挑战可通过 Chrome UA + 轻度反自动化 +
   3s 等待通过。
4. 迁移步骤：把 `via: ego` 的站改成 `via: playwright` + `playwright_wait_ms: 3000`，
   ego 仅保留为本地侦察/对照（与 ARCHITECTURE「ego 只用于侦察」一致）。

风险/未验证：
- Cloudflare **Turnstile/强风控**未验证；如果遇到，再评估 Patchright / playwright-stealth 或
  远程浏览器服务（Browserbase 目前 402 额度耗尽）。
- 持久 profile 未测（ego 能过可能也依赖已存在的 clearance cookie）；服务器上没有历史 cookie，
  需要 Playwright 全新会话通过挑战——本次 UPNG 实测是**全新会话通过**，说明 JS 挑战可解。
- `route.abort` 的带宽收益未量化（只测了耗时）；要断言"省 60%"需要统计网络字节与更大页面样本。
- 样本量小（6–8 页），结论按"方向性"使用，不代表全部站点。

## 4. 对当前项目的取舍

1. **默认直连/指纹**；`via: playwright` 只给挑战站，按站开启，不进默认依赖（`--extra browser`）。
2. **trafilatura 保持默认降噪**；readability 作为"抽太短"时的候选（可后续加为 fallback 候选并
   用同批页面验收），Crawl4AI 暂不引入。
3. **Crawl4AI/Instructor/Patchright** 等不进入主链路：当前没有站点/字段证明需要它们；先用
   `--check-extract` + `verify_coverage` 的实测数据决定。
4. 服务器部署文档：见 `deploy/README.md` 的 "Linux 服务器" 小节（新增）。
