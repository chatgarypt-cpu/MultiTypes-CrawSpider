# 南太平洋岛国信源 · 批量采集可行性调研

日期：2026-10-27
输入：`南太平洋岛国信源（采集目标）.xlsx`（109 条）、`期望数据结构.csv`（32 列样例，1,112 条）
产出：本报告 + `research/summary.csv`（逐站明细）+ `research/probe_results.json`（原始探测证据）

---

## 0. 结论

1. **109 个源里约 62%（68 个）已确认可采**，24 个域名已失效（22%），8 个被 Cloudflare/WAF 拦在本机网络外，4 个本机网络握手失败，5 个待定。失效比例不低，源清单需要更新一轮。
2. **主力是老 WordPress**：25 个站有可用的 `wp-json/wp/v2` 接口，存量文章合计 **298,471 篇**（Post-Courier 13.9 万、Cook Islands News 7.9 万、Island Times 2.1 万、EMTV 2.1 万、Radio Samoa 1.9 万、PINA 1.4 万）。这类站不需要逆向，直接分页取全文即可。
3. **其余站分三类**：9 个有 RSS、12 个只有 sitemap、21 个只能走 HTML 列表 + 正文抽取（需站点级选择器）。政府/智库站大量是静态页、无列表，内容量很小。
4. **目标格式可以复刻**：32 列里实际有值的是 14 列；WP API 能直接映射 12 列，缺失的只是社交互动计数（样例里也是空的）。正文用 trafilatura 在 Drupal/WP 站上实测可用。
5. **全量 ≠ 必要**：光 WP 站就 30 万篇，全史采集成本高、合规风险大。建议先按"近 N 年 / 每站上限"做增量，再做历史回补。

## 2. 验证方法（为什么会有"假死"）

本机网络走 FlClash TUN + fake-IP：**任何域名都解析到 198.18.x.x**，所以"连不上"不等于"站点不存在"。本次用四层交叉验证：

1. 本机直连（curl/urllib，跟随重定向，记录状态、服务器、生成器）；
2. 公网 DNS（`dns.google/resolve`）判 NXDOMAIN；
3. 外部抓取服务 `r.jina.ai` 服务端取页（绕开本机网络，同时校验站点是否真的活着）；
4. 真浏览器 `ego-browser` 打开页面并在页面内 `fetch` 接口（用于 Cloudflare 站）。

## 5. 目标格式 → 来源字段映射（WP 站）

| 目标列 | 来源 |
|---|---|
| title | `post.title.rendered`（去 HTML 实体） |
| url | `post.link` |
| channel_text | `post.categories[0]` → `/wp/v2/categories/<id>.name` |
| country_text | 源清单「国家」列 |
| lang_text | 页面 `html lang` / WP `language`（样例是 `en-US` 这种） |
| user_id / user_author_name / user_url | `post.author` → `/wp/v2/users/<id>` |
| created_at / updated_at | `post.date` / `post.modified` → ISO8601 `Z` |
| description | `post.excerpt.rendered` 去标签 |
| text | `post.content.rendered` 去标签，段落间保留 `\n\n` |
| image | `jetpack_featured_media_url` 或 `yoast_head_json.og_image[0]` |
| video / link | 正文里的 youtube/spotify embed（样例即此规则） |
| tag | `/wp/v2/tags?post=<id>`，多个用 `; ` 连接 |
| host | 域名 |
| 其余计数列 | 留空 |

非 WP 站用 trafilatura 抽 `title/date/author/text`，`channel_text` 取面包屑或 URL 一级栏目，`image` 取 `og:image`。

**实测**：`matangitonga.to`（Drupal 7）单篇 2,808 字 + 日期 + 标题；`islandtimes.org` 在浏览器内 fetch WP API 拿到 `X-WP-Total: 21375` 和完整正文。47 个直连站里 17 个能直接抽到合格正文，其余多为无文章列表的机构页，需要站点配置。

## 6. 风险与合规

- **robots**：Cloudflare 托管 robots 常见 `User-agent: * / Allow: /` + `Content-Signal: search=yes, ai-train=no`。抓取本身允许，但**不能用于模型训练**；建议在交付说明里写明"检索/引用用途"。
- **失效率高**：24/109 失效，另有 5 个待定。源清单是人工整理的，域名常年不更新。
- **反爬**：8 个 Cloudflare 挑战站 + 4 个 TLS 层拦截站。浏览器方案可行但慢（每站 3–10 秒），不建议全量走浏览器。
- **量级**：全史 30 万篇 + 图片，粗估 5–10 GB 文本+元数据；需明确时间窗。
- **语言**：法语站 13 个（la1ere、lnc.nc、tntv、upf、criobe…），正文抽取对法语同样有效，但 `lang_text` 要按实际页面判断，不能沿用清单。

## 7. 工具现状与缺口

| 能力 | 状态 | 结论 |
|---|---|---|
| REA MCP（逆向/抓包/接口发现） | ❌ 本会话未接入（只配在 Codex 里） | **需要配**，见下 |
| ego-browser（真 Chromium） | ✅ 可用，已实测通过 Cloudflare | 保留，作为反爬/JS 站通道 |
| Python + uv + trafilatura/requests | ✅ 可用（`uv run --with ...` 临时环境） | 够用，无需装 pandas |
| 本机代理（FlClash TUN） | ⚠️ fake-IP 伪造 DNS，部分站 TLS 被重置 | 给目标域名加直连/指定节点规则，或把采集跑在境外服务器 |
| 服务端抓取兜底（jina reader） | ✅ 可用但过不了 Cloudflare | 仅作校验/轻量兜底 |

### 需要配置的（按优先级）

**1）把 REA MCP 接到 DSH（当前缺口）**

`~/.codex/config.toml` 里已有 `rea`（`npx -y rea-agents@6.4.0 mcp`），但 DSH 会话里没有对应工具。在 `~/.dsh/profiles/web/cordis.patch.yml` 追加：

```yaml
- id: mcp-rea
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: rea
    transport: stdio
    command: npx
    args: ['-y', 'rea-agents@6.4.0', 'mcp']
    toolCallTimeoutMs: 300000
```

重启 `dsh web` 后生效，工具名形如 `mcp__rea__capture_browser_scenario`。用途：la1ere/tntv/samoaobserver 这类需要抓包找接口的站，以及给站点做"一次抓包 → 固化脚本"。

**2）可选的第二个 MCP：Firecrawl / Browserbase**

只有当"浏览器慢"成为瓶颈、或要把采集搬到云端定时跑时才需要。本地 ego-browser 已能覆盖目前所有反爬站，暂不必花钱。

**3）不需要**：额外爬虫框架、数据库、向量库。stdlib + requests + trafilatura + 一个 `sources.yaml` 配置表就够。

## 8. 建议的下一步

1. **先做 5 站试点**（覆盖 4 种通道）：
   - `islandtimes.org`（WP + Cloudflare）
   - `postcourier.com.pg`（WP 大站，13.9 万篇）
   - `matangitonga.to`（Drupal，RSS + 正文抽取）
   - `fijitimes.com.fj`（只有 sitemap）
   - `www.mnre.gov.ws`（政府静态站，HTML 列表）
   每站 100 条，产出可直接导入目标 32 列 CSV 的样张，验证字段与去重。
2. **建 `sources.yaml`**：每站记录 `域名 / 通道 / 列表规则 / 正文选择器 / 时间字段 / 栏目过滤 / robots 备注`，批量跑时按配置执行，不写 109 份脚本。
3. **确认三个口径**（见下）后再决定历史回补规模。

### 需要你确认

- **时间范围**：近 1 年 / 近 3 年 / 全史？
- **每站上限**：比如每站最多 1,000 条（大站只取最新），还是按日期切？
- **语言**：原文保留即可，还是需要中文翻译/摘要字段？
